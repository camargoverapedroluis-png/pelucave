# Architecture contract: Laboratorio de Sistemas Dinámicos

This is **the contract** that the builder agents code against in parallel, without talking to each other. It fixes files and owners, load order, the namespace, every public API with its signatures and return shapes, the bus events, and the CSS, testing, performance, accessibility and copy conventions.

- **What to build:** `docs/PRODUCT_SPEC.md` (the user's request, verbatim, plus the agreed interpretation).
- **How it should look and feel:** `docs/SKILLS_BRIEF.md`.
- **What each module actually does:** `docs/api/<key>.md`, written by each owner. Where an owner's actual API differs from this contract, **the actual API wins**; read its source when in doubt and record the difference in that `docs/api` file.
- **Precedence when sources disagree:** user request → PRODUCT_SPEC interpretation → this contract → SKILLS_BRIEF → individual skills. The resolved conflicts are listed in §16.

Contents: §1 Roles and ownership · §2 File tree · §3 Load order and loading rules · §4 Namespace map · §5 Module template · §6 Boot (app.js) and sections · §7 `DSL` core (ns.js) · §8 Math (`DSL.core`) · §9 Systems (`DSL.systems`) · §10 Charts (`DSL.viz.charts`) · §11 Scenes (`DSL.viz.scenes`) · §12 UI (`DSL.ui`) · §13 Bus events · §14 Conventions (CSS, HTML/JS, copy, a11y, motion, performance) · §15 Testing · §16 Decisions · §17 Change protocol · §18 Integration record · §19 Audit rounds 1 and 2 · §20 Pelucave transition.

**Loading rules**, enforced by `contract.test.mjs`, which loads every own script in a bare `node:vm`:

1. **Classic scripts only.**
   - No `import`/`export`.
   - No `type="module"`.
   - No build step.
   - Each file is one IIFE that receives `window.DSL`.
   - Modern syntax is fine (`const`/`let`, arrow functions, classes, optional chaining, `??`). The targets are current evergreen browsers opened from `file://`.
2. **Top-level code only defines things.**
   - At load time a module may read earlier modules, define functions and classes, assign its `DSL` slot, and call the registries `DSL.systems.register` and `DSL.viz.scenes.register`.
   - It must **not** touch `window.Chart`, `window.katex`, the DOM content, timers, `requestAnimationFrame` or `localStorage` at load time. Access those lazily, inside functions.
   - It must run with zero console errors when Chart.js and KaTeX are absent.
3. **Dependencies flow downward.**
   - A module may use modules loaded *before* it at load time.
   - It may use modules loaded *after* it only at call time.
   - Sections run at mount time (`DOMContentLoaded`), when everything is loaded.
4. **One global.** Only `window.DSL` is added. `window.Chart` and `window.katex` come from vendor.
5. **No network, ever.** Everything is local (`vendor/`), and the `file://` page must work offline. The single-file build inlines everything (§15.4).

An inline `<script>` in `<head>` (in `index.html`) does two things before first paint: it applies the saved theme, and it adds the class `js` to `<html>`.

## 5. Module template

```js
/*
 * js/<path>.js — Propietario: <owner key>.
 * <Una línea: qué hace>. API: docs/api/<key>.md.
 */
(function (DSL) {
  'use strict';

  // Dependencias cargadas antes (seguras en tiempo de carga):
  var util = DSL.util;

  function privateHelper() { /* … */ }

  DSL.<slot> = {
    publicFn: function () { /* … */ }
  };
})(window.DSL);
```

- Identifiers are in English. Comments are short and in Spanish. UI strings are in Spanish (§14.3).
- Errors from programmer misuse: `throw new Error('<mensaje en español>')`. Validation of user input returns messages, never throws to the console.
- Reserve `console.error` for real faults (tests fail on it). `console.warn` is only for developer misuse, such as an unknown icon. Do not use `console.log` in shipped code.

## 6. Boot and sections

### 6.1 `js/app.js` (design-system; the architect's stub already works)

On `DOMContentLoaded` (through `DSL.util.ready`), `app.js` does the following:

1. Calls `DSL.ui.tooltips.init(document)` if it exists.
2. For each `[data-mount]`, in document order and inside `try/catch`:
   - `shell-header` → `DSL.ui.shell.mountHeader(el)`, and `shell-footer` → `DSL.ui.shell.mountFooter(el)`. These are skipped silently if `DSL.ui.shell` is missing.
   - Any other name → `DSL.sections[name].mount(el)`.
   - It stores the returned handle in `DSL.app.handles[name]`.
   - On failure it renders `<div class="app-error" role="alert" data-testid="app-error-<name>">` with a Spanish message. It also calls `console.error('[app] No se pudo montar «name»:', err)` and continues.
3. Sets `DSL.app.ready = true` and `<html data-ready="true">`, then emits `app:ready` with `{ mounted: string[], failed: string[] }`.

Tests wait on `html[data-ready="true"]` (the `gotoApp` fixture).

**One clean first paint (audit round 1, FND-06).** `css/base.css` hides `.app-header`, `.app-main` and `.app-footer` with `visibility: hidden` while `html.js:not([data-ready])`. Invisible boxes do not count as layout shifts, so the mount loop no longer moves visible content (CLS was 0.43–0.90; it is now below 0.05 at 1440, 1024, 820 and 390 px, in `src` and `dist`). On `data-ready` the three fade in once over `--dur-reveal` (no fade under reduced motion). A 3 s fallback keyframe shows them if `data-ready` never arrives. Without JavaScript there is no `html.js`, so the `noscript` text shows as before.

### 6.2 Section modules

```js
DSL.sections.<key> = {
  mount(el) → { destroy() }        // el = the <div data-mount="<key>"> inside its <section>
};
```

| key | section id | heading the module must render | owner |
|---|---|---|---|
| `hero` | `#inicio` | `<h1 id="inicio-title">` (the only h1 on the page) | hero-concepts |
| `concepts` | `#conceptos` | `<h2 id="conceptos-title">` | hero-concepts |
| `wizard` | `#modelado` | `<h2 id="modelado-title">` | wizard |
| `gallery` | `#galeria` | `<h2 id="galeria-title">` | gallery |
| `bikeLab` | `#galeria` (second `[data-mount]`, after `gallery`) | `<h3>` inside its own `article` (the section keeps the gallery's `h2`) | bikelab |
| `tfengine` | `#transferencia` | `<h2 id="transferencia-title">` | tfengine |

- `index.html` fixes `<section id aria-labelledby="<id>-title" data-testid="section-<id>" class="app-section">`. The module renders the heading with that id.
- Render only inside `el`. Never touch another section's DOM; cross-section communication goes only through `DSL.bus` (§13).
- `mount` is synchronous and cheap. Defer heavy work (Chart.js charts, KaTeX blocks, precomputation, animation loops) until the section approaches the viewport, or until idle (`requestIdleCallback`, falling back to `setTimeout`).
- **As built after audit round 1 (FND-07 with HC-12, WZ-08, GAL-12, TFE-15).** The four heavy sections build through `DSL.util.lazyInit(el, phases, { rootMargin })` (§7.3, `docs/api/ns.md`). Each section, or each concept card, is split into phases of about 50 ms or less at 1× CPU. A shared idle queue runs one phase per idle callback, starting 800 ms after `app:ready`. When an element comes within its `rootMargin` (concept cards and gallery 200 px, tfengine 300 px, wizard 400 px), its remaining phases run synchronously, so it is never blank on screen. Audit round 2 measured the alternative, one phase per frame on that path (request R13), and declined it because it leaves sections visibly unbuilt for several frames after a jump (`docs/AUDIT.md`, «Ronda 2»). `ensure()` finishes it at once; `concepts:open`, `gallery:open` and `tf:open` call it. When done, the element gets `data-lazy="done"`; about 5 s after load every section has it without any scrolling. Before it is built, a section reserves its built height (wizard step 1 and the gallery stage per breakpoint, concept chart frames by aspect-ratio), so a jump past it lands on target. Each module keeps its `util.onVisible` path as a fallback when `lazyInit` is absent.
- Events can arrive before the lazy init has run. Example: `tf:open` arriving before `#transferencia` was ever visible. Keep the payload and apply it when initialisation finishes.
- `destroy()` stops loops and observers, destroys charts and scenes, and unsubscribes from the bus.
- A section may expose pure helpers for unit tests as `DSL.sections.<key>.helpers`.

## 7. `DSL` core: `js/core/ns.js` (architect)

The full reference is `docs/api/ns.md`. Summary:

### 7.1 Bus

| Signature | Behaviour |
|---|---|
| `DSL.bus.on(event, fn)` | Subscribes. Returns `unsubscribe()`, which is idempotent. `fn(payload, event)` |
| `DSL.bus.once(event, fn)` | Subscribes for one call. Returns `unsubscribe()` |
| `DSL.bus.off(event, fn)` | Unsubscribes |
| `DSL.bus.emit(event, payload)` | Calls handlers synchronously, in subscription order. Returns the count. A throwing handler is reported through `console.error` and the others still run |
| `DSL.bus.count(event)` | Number of handlers |
| `DSL.bus.clear([event])` | Removes handlers |
| `DSL.util.emitter()` | A new independent `{ on, off, once, emit, count, clear }`, e.g. for `Simulator` |

### 7.2 Preferences

- `DSL.prefs.reducedMotion` is a live boolean that tracks `(prefers-reduced-motion: reduce)` and emits `motion:change` `{ reducedMotion }`.
- `DSL.prefs.setReducedMotion(true|false|null)` forces the value; `null` returns control to the system.
- The query parameter `?movimiento=normal|reducido` forces the value for that page load only (nothing is persisted). It exists for local checks on machines whose OS reports `prefers-reduced-motion: reduce` (Windows Server with visual effects off): there, every animation in the app, the Pelucave transition included, is replaced by an instant change by design.
- `DSL.prefs.theme` is `'dark' | 'light'`, read from `<html data-theme>`.
- `DSL.prefs.setTheme(theme, { persist = true })` does four things: sets `data-theme`, saves to `localStorage['dsl.v1.theme']` as JSON inside try/catch, updates `<meta name="theme-color">` to `--bg`, and emits `theme:change` `{ theme }` when the theme changed.
- `DSL.prefs.toggleTheme()` switches between the two themes.
- **The theme is the only thing ever persisted.**

### 7.3 Utilities

| Signature | Notes |
|---|---|
| `clamp(x, lo, hi)`, `lerp(a, b, t)`, `invLerp(a, b, x)` | |
| `formatNumber(x, digits = 4, { decimals, sci = 'unicode' \| 'e', sciMin = 1e-3, sciMax = 1e6, ascii = false, plus = false })` | Uses the decimal point `.` and trims zeros. Typographic minus `−` unless `ascii`. Scientific notation `1.2×10⁻⁵` (or `1.2e-5`) outside the [sciMin, sciMax) range. `NaN` → `—`, `±Infinity` → `∞`/`−∞`. `digits` = significant digits; `decimals` = fixed decimals |
| `parseNumber(str)` | Accepts `,` or `.` as the decimal mark, `−`, `e` notation, `1.5×10⁻³`, `2x10^3` and `2*10^(-2)`. Returns `NaN` if invalid. No thousands separators |
| `now()` | `performance.now()` |
| `debounce(fn, ms)` | Returns `f` with `.cancel()`, `.flush()` and `.pending()`. Fires on the trailing edge |
| `throttle(fn, ms)` | Fires on the leading edge, plus a trailing edge with the last arguments. Has `.cancel()` |
| `mulberry32(seed)` | Returns `rng()` in [0, 1). **Use it instead of `Math.random`**, which is forbidden |
| `gaussian(rng)` | N(0, 1) by Box–Muller |
| `cssVar(name, el?)` | Trimmed computed value of `--name`; `''` if unknown |
| `uid(prefix = 'dsl')` | `'prefix-N'`, deterministic per page load |
| `escapeHtml(s)` | |
| `h(tag, props, ...children)` | Creates an HTML element. ## 8. Math: `DSL.core` (math)

All numeric functions are pure and deterministic, with no DOM access. **Polynomials are arrays of real coefficients in descending powers**: `[a_n, …, a_1, a_0]`, so `s² + 2s + 5` is `[1, 2, 5]`.

### 8.1 `DSL.core.numeric` (`js/core/numeric.js`)

**Polynomials** (`N.poly`):

| Signature | Returns / notes |
|---|---|
| `trim(p, eps = 0)` | Drops leading coefficients with `|c| ≤ eps·max|c|`. The zero polynomial is `[0]` |

**Roots** (`N.polyRoots(coeffs, { tol = 1e-12, maxIter = 500 })`) returns a complex array whose length equals the degree after trimming.

- **Method:** exact zero roots for trailing zero coefficients, then Aberth–Ehrlich (or Durand–Kerner) from deterministic initial points, then Newton polishing on the original polynomial. No randomness.
- **Cleanup:**
  - `|im| ≤ 1e-9·max(1, |z|)` → `im = 0` exactly.
  - Conjugate pairs are made exactly conjugate.
  - Repeated roots come out clustered within ~1e-6 and are **not** averaged into fake exactness. `tf` groups them (§8.2).
- **Order:** ascending real part, then ascending imaginary part, with ties within `1e-9·scale`. A conjugate pair is therefore adjacent, with the negative imaginary part first.
- Degree 0 → `[]`. Throws on the zero polynomial.

**Integrators** share one signature:

```
N.integrate(f, x0, t0, t1, opts) → { t: number[], x: number[][], stats }
  f(t, x: number[]) → number[]        (dx/dt)
  opts.method   'euler' | 'heun' | 'rk4' | 'rk45'     default 'rk4'
  opts.dt       fixed step (euler/heun/rk4, required); initial step for rk45 (default (t1−t0)/100)
  opts.rtol     1e-6   (rk45)          opts.atol 1e-9 (rk45)
  opts.maxSteps 100000                 opts.dtMin, opts.dtMax (rk45)
  opts.tEval    optional ascending times within [t0, t1]: output only there (cubic Hermite dense output)
  stats = { method, steps, rejected, fevals, success: boolean, message: string (Spanish) }
```

- **Fixed-step methods** take `ceil((t1 − t0)/dt − 1e-9)` steps, and the last step is shortened so it lands exactly on `t1`.
- **Output:** `t[0] = t0` and the last entry is `t1`, unless `maxSteps` is hit. In that case `success = false` and the partial result is returned; nothing is thrown.
- **`rk45`** is Dormand–Prince 5(4) with FSAL and a standard step-size controller.
- `t1 < t0` throws.

**Single steps** return the new state (written into `out` if given, to avoid allocations in frame loops):

```
N.eulerStep(f, t, x, dt, out?)
N.heunStep(f, t, x, dt, out?)
N.rk4Step(f, t, x, dt, out?)
N.steppers                           { euler, heun, rk4 }  (same functions)
```

### 8.2 `DSL.core.tf` (`js/core/tf.js`)

```js
const { TransferFunction, TFInputError, partialFractions } = DSL.core.tf;
const G = new TransferFunction(num, den);
```

**Constructor:** `new TransferFunction(num, den)`.

- Coefficients are finite numbers in descending powers.
- Both polynomials are trimmed with `eps = 1e-14`. Then num and den are both divided by `den[0]`, so **the denominator is monic**.
- It throws `TFInputError` (Spanish message) when:
  - the denominator is zero, or of degree 0;
  - `deg(num) > deg(den)` (improper);
  - any coefficient is not finite.
- There is **no automatic pole–zero cancellation**.

**`TFInputError`** extends `Error`, with these fields:

| Field | Values |
|---|---|
| `name` | `'TFInputError'` |
| `field` | `'num' \| 'den' \| null` |
| `code` | `'empty' \| 'token' \| 'nonfinite' \| 'den-zero' \| 'den-degree' \| 'improper'` |
| `token` | the offending text, when applicable |
| `message` | Spanish, saying what failed and how to fix it |

**Read-only properties:** `num` (frozen array), `den` (frozen, monic), `order` (= deg den), `relativeDegree`, `isStrictlyProper`.

**Methods:**

| Method | Returns |
|---|---|
| `poles()` | complex[], in `polyRoots` order (cached) |
| `zeros()` | complex[] (cached) |
| `dcGain()` | `num(0)/den(0)`; `±Infinity` with a pole at the origin; `NaN` if both are 0 |
| `stability()` | `'estable'` (every Re p < −ε); `'inestable'` (some Re p > ε, or a repeated pole on the jω axis); `'marginal'` (simple poles on the jω axis, the rest stable). ε = 1e-9·scale |
| `isStable()` | `stability() === 'estable'` |
| `routh()` | `{ rows: number[][], labels: string[] /* TeX: 's^{3}' */, firstColumn: number[], signChanges: number, special: null \| { type: 'zero-first-column', row, epsilon } \| { type: 'zero-row', row, auxiliary: number[] }, notes: string[] }` |

**Changed in audit round 1** (details and examples in `docs/api/tf.md`):

- **Stability (CORE-09).** `stability()` and `stabilityInfo()` decide first from the Routh–Hurwitz sign pattern of the denominator. Only a zero row or a zero first-column entry triggers the per-pole jω-axis analysis, with the tolerance |Re p| ≤ 1e-9·max(1, |p|) taken per pole. The table row above (ε = 1e-9·scale) no longer applies: stiff or very slow systems such as 1e-10·s² + s + 1 are `'estable'`. `stabilityInfo()` also returns `method` (`'routh'` or `'polos'`) and `slowTau`, and its `reason` gets a «modo más lento» sentence when 6τ exceeds the 10⁵ s horizon cap.
- **Bode phase (CORE-06).** For a negative static gain both anchors, +180° and −180°, are tried, and the one whose unwrapped phase has the smaller max|φ| over the plotted grid is kept (a tie keeps +180°). So 1/(s − 2) runs from −180° to −90°.
- **Displayed digits (CORE-01).** Residue parts below 1e-12·|r| are set to 0. `stepDisplayDigits()` returns the smallest d in {4, 6, 8, 10, 12} whose rounded poles and residues rebuild the step response within 1e-3·max|y| and keep distinct poles distinct. `stepAnalytic({ digits })` and `impulseAnalytic({ digits })` use it by default, and add a note when two poles agree within 1e-3. `stepSamples()` and `impulseSamples()` set |y| < 1e-12·max|y| to 0, so y(0) is exactly 0 for a strictly proper G.
- **`stepInfo()` (CORE-10, CORE-11).** It adds `limitValue`: the finite limit when a zero cancels the pole at the origin (the verdict stays `'marginal'` and `finalValue` stays `null`). Its grid has max(`n`, 20 samples per period of the fastest oscillation) points, capped at 200001, plus a grid of ≥ 50 samples per period over the first 4 periods for the first peak and the 10 %/90 % crossings. A measured tp, Mp or tr that differs by more than 5 % from the exact value of a pure second order is discarded with a note. A note always states the samples and window actually used.

A `Term` is one of two shapes:

- `{ kind: 'real', p, k, c, tex }` contributes `c·t^{k−1}/(k−1)!·e^{p t}`.
- `{ kind: 'osc', sigma, omega, k, A, B, tex }` contributes `t^{k−1}/(k−1)!·e^{σt}(A cos ωt + B sin ωt)`, with ω > 0.

**Static constructors:**

| Signature | Notes |
|---|---|
| `TransferFunction.fromFirstOrder(K, tau)` | `K/(τ s + 1)` |
| `TransferFunction.fromSecondOrder(K, zeta, wn)` | `K ωn²/(s² + 2ζωn s + ωn²)` |
| `TransferFunction.parseCoeffs(str, field)` | `number[]`. Throws `TFInputError` |
| `TransferFunction.fromCoeffStrings(numStr, denStr, { maxDenDegree = 4 })` | Throws `TFInputError` |

Coefficient text format:

- Separate coefficients with spaces or `;`. Brackets are optional.
- Each coefficient is parsed with `DSL.util.parseNumber`, so the decimal mark may be `,` or `.`.
- A trailing comma after a token counts as a separator (`"1, 2, 3"` works). `"1,2,3"` is rejected with a message suggesting spaces.
- Example message: «Separe los coeficientes con espacios; la coma o el punto marcan los decimales.»

The module-level helper `DSL.core.tf.partialFractions(num, den)` returns the same shape as `partialFractionsStep()`, for any strictly proper rational function.

- **Readout corrections.** The mass-spring «Tiempo de establecimiento» is the exact 2 % value for ζ ≥ 1 and 4/(ζωn), marked approximate, only for 0 < ζ < 1 (CORE-02). The RLC decay constant becomes «Constante de tiempo dominante» −1/p_lenta when overdamped (CORE-03).

### 9.4 Simulator (`js/systems/simulator.js`)

```
const sim = new DSL.systems.Simulator(modelOrId, { variant, params, input = { type: 'escalon', amplitude: 1 }, speed = 1,
                                                   historySize = 2400, dt /*override hints.dt*/ })
```

**Methods:**

| Signature | Behaviour |
|---|---|
| `sim.step(realDt)` | Returns the number of substeps or iterations advanced. Continuous: `acc += realDt·speed·timeScale`; while `acc ≥ dt`, one fixed RK4 substep (at most 2000 per call, deterministically discarding the rest). Discrete: `acc += realDt·speed·timeScale`; while `acc ≥ 1`, `x = next(k, …)` and `k++`. Records one history sample and emits `'step'` only when it advanced |
| `sim.advance(simAmount)` | Advances exactly `simAmount` simulated time units (continuous) or iterations (discrete), ignoring speed |
| `sim.reset()` | t = 0, k = 0, x = x0. Clears the history, records the initial sample, emits `'reset'` |
| `sim.setParams(partial)` | Merges `partial`; applies live, unless a changed param has `live: false`, in which case it calls `reset()`. Emits `'params'` `{ params }` |
| `sim.setInput(spec)` | |
| `sim.setSpeed(x)` | 0.25 … 4 |
| `sim.setVariant(id)` | Resets: keeps the current values of keys that exist in the new variant, and uses the defaults for the rest |
| `sim.on('step' \| 'reset' \| 'params', fn)` | Returns `unsubscribe` |
| `sim.destroy()` | |

**Read-only getters:**

- `t`, `k`, `u`, `speed`, `variant`
- `state` (copy), `outputs` (`{ key: value }`), `params` (copy), `input` (copy)
- `history`: a ring buffer `{ length, capacity, get(i) /*0 = oldest*/, last(), toArray(), forEach(fn), clear() }` of `{ t, outputs, state, u }`

For a discrete variant, `t === k` (time is measured in periods).

The `'step'` payload is `{ t, state, outputs, u, substeps }`.

**Halts** (as built; audit round 1 added the domain guard): a non-finite state or one beyond the state bound halts the simulation, and so does a reason returned by the model's `domain` hook. `sim.halted` is then `{ t, reason, kind? }` and `'halt'` is emitted with the same payload; `kind: 'dominio'` marks a domain exit, so listeners need not parse the Spanish text. `reset()` clears it.

**Deterministic:** the same sequence of calls gives the same states, bit for bit.

## 10. Charts: `DSL.viz.charts` (charts)

**Common to every factory:**

- **Canvas and size.** It takes a `<canvas>` whose parent is a `.ch-frame` element sized by the owner's CSS (an `aspect-ratio`, so the space is reserved and there is no layout shift). Chart.js runs with `responsive: true, maintainAspectRatio: false`.
- **Accessibility.** `opts.ariaLabel` puts `role="img"` and `aria-label` on the canvas. `handle.describe(text)` updates it, e.g. «Respuesta al escalón: sobrepaso 16 %, establecimiento 4.0 s».
- **Handle.** Every factory returns a handle with `destroy()` and a read-only `chart`, the Chart.js instance (`charts` for Bode).
- **Theme.** Colours are given as **token names** (`'--c-out'`) and resolved through `DSL.util.cssVar`. Charts re-theme on `theme:change`.
- **Reduced motion.** With `DSL.prefs.reducedMotion`, there is no animation (`update('none')`). Charts follow `motion:change`.
- **Data.** The engine samples; Chart.js only draws. Data is passed already parsed (`parsing: false`, `normalized: true`), and there are no point markers on lines (`pointRadius: 0`).
- **Missing Chart.js.** If `window.Chart` is missing, the factory returns an inert handle (every method is a no-op) and warns once.
- **Axis titles** are in Spanish, with units: «Tiempo t (s)», «Amplitud», «Frecuencia ω (rad/s)», «Magnitud (dB)», «Fase (°)».

**Theme helpers:**

| Signature | Returns / notes |
|---|---|
| `theme()` | `{ ink, muted, grid, axis, plotBg, font, colors: { in, out, state, pole, zero, ghost, s1…s6 } }` |
| `color(token)` | String colour for `'--c-out'` or `'c-out'` |
| `applyDefaults()` | Idempotent. Called automatically by the first factory and on `theme:change` |

**Factories:**

- **`createTimeChart(canvas, opts)`** → `{ push(t, values), pushMany(samples), setSeries(series), setWindow(s), setYRange(r), clear(), resize(), describe(text), destroy(), chart }`
  - `opts`: `series: [{ key, label, color, dash?, unit? }]`, `xLabel = 'Tiempo t (s)'`, `yLabel`, `window = 10` (null = everything), `yRange = 'auto'` or `[min, max]`, `maxPoints = 2000`, `discrete = false`, `ariaLabel`.
  - `push(t, { [key]: number })` buffers the sample. At most one redraw per animation frame.
- **`createStepChart(canvas, { xLabel, yLabel = 'Amplitud', ariaLabel, showBand = true })`** → `{ update(curves, opts), clearGhost(), describe(text), destroy(), chart }`
  - `curves` is `[{ key, label, t: number[], y: number[], color = '--c-out', dash? }]`.
  - `update` opts: `ghost = true`, `annotations` (below), `mode = 'release' | 'drag'`.
  - **Morph:** y is interpolated from the previous curve over 300 ms (`'release'`), 120 ms (`'drag'`), or 0 ms with reduced motion.
  - **Ghost:** the previous curve, in the same hue at `--ghost-opacity`, dashed, until the next update.
  - **Annotations** (`annotations`): `finalValue` (y∞, dashed `--c-in`), the ±`band` (2 %) band, `peak: { t, y }`, `settlingTime` (vertical marker, 2 % criterion stated in the label), `riseTime: { t10, t90 }`.
- **`createPoleZeroChart(canvas, { ariaLabel })`** → `{ update({ poles, zeros }, { mode }), describe, destroy, chart }`
  - Equal 1:1 aspect, axes through the origin and an emphasised jω axis.
  - Left half-plane shaded with `--c-stable-region`, right half-plane tinted with `--c-unstable-region`.
  - Symmetric auto-range with padding.
  - Poles drawn as × and zeros as hollow ○, both 10 px.
  - Poles move smoothly between updates, matched by sorted index.
- **`createBodeChart(magCanvas, phaseCanvas, { ariaLabel })`** → `{ update(bode, { ghost = true, mode }), describe, destroy, charts: [mag, phase] }`
  - `bode` is `{ omega, magDb, phaseDeg }`.
  - Log ω axis shared by both charts, magnitude above and phase below.
- **`createXYChart(canvas, { xLabel, yLabel, aspect = 'auto' | 'equal', xRange?, yRange?, ariaLabel })`** → `{ update(datasets, { mode }), describe, destroy, chart }`
  - `datasets` is `[{ key, label, kind: 'line' | 'points' | 'stems' | 'steps' | 'segments', points: [{ x, y }], color, dash?, fill? }]`.
  - `'segments'` draws pairs of points (the cobweb); `'stems'` draws discrete-time stems.
  - Use it for phase portraits, cobwebs and discrete sequences.

**Data table:** `dataTable(container, { caption, columns: [{ key, label, unit }], rows: object[], maxRows = 200 })` returns an `HTMLTableElement` for the «Ver datos» toggle.

**Changed in audit round 1** (details in `docs/api/charts.md`):

- **«Ver datos» follows the data (FND-01, FND-02).** Every data-changing call schedules a trailing refresh of the chart's open tables: at the end of the morph or at most 150 ms after the last call, and at most twice per second for a streaming time chart. Toggles created with `dataToggle(handle, …)` register with their chart, so they refresh too. Sampling is per series: a series of 60 rows or fewer keeps every row, and the caption gives the count per series.
- **Axes (FND-03).** While tweening, the tick step comes from the displayed range, so there are no tick-limit warnings. Fixed ranges and the pole-zero map use nice steps anchored at 0, overlapping labels are dropped, and |v| ≥ 1e5 uses compact labels («−5×10⁵») with the axis width measured from them. The time chart builds its first configuration from `opts.yRange`.
- **Off screen (FND-04).** See «As built» below: one coalesced render per chart, 400 ms after the last change; `DSL.viz.charts.flush()` and `beforeprint` draw everything pending.
- **First reveal (FND-05).** The reveal wipe waits for the chart's first visibility and plays once; stems and dots are clipped with the curve. No wipe under reduced motion.
- **Smaller additions.** `setXRange([min, max])` on the XY handle (FND, HC-10); legend swatches draw each series' own dash array (FND-18); the keyboard hint mentions «modo de foco» and «Ver datos» (FND-19); resolved token colours are memoised per theme and rebuilt on `theme:change`.

**As built** (details in `docs/api/charts.md`, «Deviations»): the handles carry extra members (`tableSpec()`, `stats()`, frame data, `testid`, `alive`, `resize()`; the time chart adds `setData()`) and the factories extra options (`testid`, `legend`, `dataToggle`, and per chart `markers`/`color` or `xUnit`/`xSymbol`/`fps`). Chart.js only draws (`events: []`, its tooltip and legend plugins off, `animation: false`); hover, touch, keyboard, crosshair, glass tooltip, HTML legend and the morph/ghost tweens belong to the layer, and a chart off screen jumps to its final state. The canvas sits in `div.ch-plot` inside the `.ch-frame`. The step chart accepts `DSL.core.tf.stepInfo()` directly as `annotations`. Negative numbers use the typographic minus.

## 11. Scenes: `DSL.viz.scenes` (scenes)


Scene ids are `massSpring`, `tanks`, `rlc`, `sir` and `market`.

**As built** (details in `docs/api/scenes.md`): a `SceneInstance` also has `el`, `testid`, `summary()` and `setVariant()`; `create()` accepts `testid` (default `sc-<id>`) and `live` (polite summary); each scene adds a visually hidden sibling `<p class="sc-summary">` referenced by `aria-describedby` and sets `data-variant`; `css/scenes.css` provides the `.sc-stage` helper (`--sc-aspect`, `--sc-min-height`). Rules:

- **Container and DOM.** The owner sizes the container (gallery: `aspect-ratio`). The scene appends its own `<svg>` or `<canvas>` with the class `sc-root`, carries `role="img"` and a Spanish `aria-label`, and draws on tier-C solid surfaces.
- **Pure views.** `render(frame)` is presentation only: the physics belongs to the Simulator. `frame.dt` drives only decorative motion that follows the state (surface ripples; current dots whose speed and direction follow i(t)). With `DSL.prefs.reducedMotion`, decorative motion stops and the state is still shown (levels, positions, direction arrows).
- **Cost.** No allocations in `render`. Batch layout reads in `resize()`.
- **Visual content** (PRODUCT_SPEC §2.4):
  - `massSpring`: spring stretching, mass and damper.
  - `tanks`: fluid levels with a surface wave, inflow and outflow streams, all three variants.
  - `rlc`: current-flow dots, capacitor charge fill, inductor glow.
  - `sir`: stock-and-flow diagram with animated flows and a population dot grid.
  - `market`: supply/demand diagram, with an animated cobweb (`telarana`) or a price marker (`walras`).

## 14. Conventions

### 14.1 CSS

- **Layers.** `tokens.css` declares `@layer reset, base, components, shell, charts, scenes, sections, overrides;`. Each file wraps its rules in its own layer:

  | File | Layer |
  |---|---|
  | base.css | `reset` + `base` |
  | components.css | `components` |
  | shell.css | `shell` |
  | charts.css | `charts` |
  | scenes.css | `scenes` |
  | every section file | `sections` |
  | integrator only | `overrides` |

  A later layer beats an earlier one without a specificity fight. Tokens are custom properties and stay unlayered.
- **Prefixes.** Every class starts with its owner's prefix (§1). State classes are `is-*` and are scoped under the component (`.gl-card.is-active`).
- **Specificity.** No id selectors. Keep to ≤ 0,2,0. No `!important`, except the reduced-motion safety net in `base.css`.
- **Tokens only.** `css/tokens.css` is the only file with literal colours; `contract.test.mjs` checks this. Spacing, radii, durations, easings, z-index and type sizes come from tokens. Literal lengths are fine for 1 px hairlines and component-internal geometry.
- **Token names are frozen.** design-system may tune values and **add** tokens, but never rename or remove one. Use these groups:

  | Group | Tokens |
  |---|---|
  | Surfaces and lines | `--bg`, `--surface-1..3`, `--line` |
  | Text and accent | `--ink`, `--muted`, `--subtle`, `--accent`, `--accent-ink` |
  | Status | `--success`, `--warning`, `--danger`, `--info` |
  | Data colours | `--c-in`, `--c-out`, `--c-state`, `--c-pole`, `--c-zero`, `--c-ghost`, `--c-grid`, `--c-axis`, `--c-series-1..6` |
  | Glass | `--glass-a-*`, `--glass-b-*`, `--glass-c-bg`, `--glass-blur-*` |
  | Type | `--text-*`, `--fw-*`, `--lh-*` |
  | Space and shape | `--space-1..10`, `--radius-*` |
  | Motion and stacking | `--dur-*`, `--ease-*`, `--z-*` |

  Every value is in `css/tokens.css`.
- **Data colours on canvas** are `#RRGGBB` or `#RRGGBBAA` (Chart.js and canvas parse them). Read them with `DSL.util.cssVar` at draw-setup time, and again on `theme:change`.
- **Glass tiers** (SKILLS_BRIEF §1):
  - Tier A (`backdrop-filter`) only on the fixed bar, the simulation dock, dialogs and sheets, and tooltips and popovers. At most 3 on screen; never glass on glass.
  - Tier B (`--glass-b-bg`, no blur) on panels and cards.
  - Tier C (solid, `--glass-c-bg` / `--c-plot-bg`) under all data.
  - The reduced-transparency fallback is already built into the tokens.
- **Breakpoints** (literal values; media queries cannot read `var()`):

  | Range | Media query |
  |---|---|
  | phone | `(max-width: 767.98px)` |
  | tablet | `(min-width: 768px) and (max-width: 1279.98px)` |
  | desktop | `(min-width: 1280px)` |

  Below 768 px, layouts collapse to one column with no horizontal scroll at 375 px. Flex and grid children get `min-width: 0`.
- **Sections** get `scroll-margin-top: var(--header-h)` from `base.css`.

### 14.2 HTML and JS

- **Accessible names.** `<button>` is for actions and `<a href>` for navigation. No clickable divs. Every icon-only button has a Spanish `aria-label`.
- **IDs.** Fixed ids are only `<section>-title`. Generate the ids used in ARIA relationships with `DSL.util.uid('<prefix>')`.
- **Test ids** use `data-testid="<prefix>-<name>"` in kebab case and are unique on the page:
  - per item: `gl-system-<id>`, `tf-step-<n>`, `wz-step-<n>`;
  - transport buttons: `<prefix>-play`, `<prefix>-reset`, `<prefix>-speed`.
- **Heading levels:** h1 only in the hero; h2 per section; h3 for cards and steps; h4 only when needed.
- **Building DOM.** Use `DSL.util.h`/`svg`. Use `innerHTML` only with the module's own constant markup, never with text derived from input.
- **Formatting numbers.** Use `DSL.util.formatNumber` for text and `DSL.core.latex.num` for TeX. The decimal mark is the point. Put a non-breaking space between number and unit: `formatNumber(2) + ' Ω'`. Parse input with `DSL.util.parseNumber`, which accepts `,`.
- **Determinism.** Never use `Math.random`; use `DSL.util.mulberry32(seed)`. Use time (`DSL.util.now`) only for frame timing, never in the maths. Sorts need explicit tie-breakers.
- **Persistence.** Only the theme is persisted, through `DSL.prefs.setTheme`. Nothing else goes into `localStorage`.

### 14.3 Spanish microcopy

- **Voice.** Calm, precise and written for the learner. Sentence case and plain verbs. Name things by what they are.
- **Banned words:** «fácil», «simple», «rápido», «simplemente», «Comenzar», «Saber más». No emoji, invented statistics, ALL-CAPS labels or eyebrow labels.
- **Canonical labels.** Use them everywhere, with these exact words:

  | Label | Where |
  |---|---|
  | «Reproducir» / «Pausar» | play/pause toggle |
  | «Reiniciar» | reset |
  | «Velocidad» | speed |
  | «Restablecer parámetros» | parameter reset, with an undo toast |
  | «Ver G(s) paso a paso» | gallery → tfengine |
  | «Paso siguiente» / «Mostrar todo» | derivation |
  | «Anterior» / «Siguiente», or «Ir a: <paso>» | wizard |
  | «Ver datos» / «Ocultar datos» | chart data tables |
  | «Tema claro» / «Tema oscuro» | theme toggle |
  | «Entrada» / «Salida» / «Parámetros» | — |
  | «Escalón», «Pulso», «Senoidal» | input types |

- **Errors** say what failed and how to fix it, in the interface's voice, without apologising. An empty state invites an action.
- **Punctuation and markup.** Use the real ellipsis («Calculando…») and Spanish quotes «…». Wrap math symbols in running text in `<span translate="no">`, or render them with KaTeX.

### 14.4 Accessibility

- **Structure.** Landmarks come from `index.html` (`header`, `main#contenido`, `footer`, the skip link). Each `section` is labelled by its heading.
- **Keyboard.** Everything is keyboard-operable:
  - wizard: arrow keys;
  - tabs and segmented controls: arrows, Home and End;
  - sliders: native keys;
  - Esc closes tooltips, sheets and popovers.
- **Focus.** A visible `:focus-visible` ring: `--focus-ring`, offset `--focus-offset`. Never remove an outline without a replacement.
- **Live regions.** Polite only (`DSL.ui.announce`, or `readout({ live: true })`), for key results: a recalculated G(s) with its ζ/ωn/stability, the wizard step, the RMSE after calibration. Never per frame.
- **Charts and scenes** carry `role="img"` and a generated `aria-label` summary. Every chart also has a «Ver datos» table.
- **Contrast.** WCAG AA (4.5:1 for text, 3:1 for UI parts and large text), measured on the solid fallback. De-emphasis never uses opacity on text: dimmed parts use `--muted` text and dimmed strokes (audit round 1: HC-05, WZ-06, TFE-10). Labels drawn over fluid get a plot-background halo (SCN-02, WZ-06).
- **Forced colours** (audit round 1: FND-11, FND-12, GAL-06). `@media (forced-colors: active)` rules keep the play glyph, selected segment, tab and nav link, switch, slider, selected gallery card and KaTeX accents visible with system colours.
- **Touch targets.** With `(pointer: coarse)`, interactive controls are at least 44 px tall (`--control-h-sm`).
- **Announcements.** Live updates from dragging or key repeats are debounced to about 450 ms and announce only the settled value; nothing is announced on initial render, lazy init or programmatic restores (GAL-08, WZ-04, TFE-11).

### 14.5 Motion and reduced motion

- **Purpose.** Motion explains something: simulations, curves morphing, poles moving, wizard and derivation sequencing, panels opening, confirmations. There is no ambient decoration: no pulsing, no shimmer, no parallax, no scroll-triggered fade-ups on every section. The home load sequence runs once (≤ 700 ms total).
- **Implementation.** Animate only `transform`, `opacity` and `clip-path`; colour and background changes are allowed for hover and toggle states. Never use `transition: all`. Use the easing and duration tokens. No bounce or elastic curves; never `scale(0)`.
- **Under `DSL.prefs.reducedMotion` / `prefers-reduced-motion`:**
  - opacity and colour changes stay; travel and scale go (the tokens already zero them);
  - charts update with `'none'`;
  - simulations **start paused**, still run on demand, and show their end state;
  - the hero canvas renders one static frame;
  - decorative scene motion stops.

### 14.6 Performance

- **One ticker.** `DSL.util.loop` is the only rAF driver. Simulations use fixed-dt RK4 substeps (Simulator) and draw separately. Loops pause when off-screen (`element` option) and while the tab is hidden.
- **Canvas.** Sized with `DSL.util.observeSize` and `fitCanvas`: DPR capped at 2, no layout reads inside the frame loop, reads batched before writes.
- **Charts.** At most one update per frame; `update('none')` while streaming or dragging. Sample in the engine:

  | Plot | Samples |
  |---|---|
  | Step and impulse response (tfengine) | N = clamp(⌈20·T·max\|Im p\|/(2π)⌉, 400, 20000) over the window T (audit round 1, TFE-05): 400 for the default systems, at least 20 per period for fast oscillations |
  | Bode | 300 log-spaced ω |
  | Live time series | ≤ 2000 points |

- **Hot loops.** No allocations: preallocate, use `out` parameters (`rk4Step`) and hoist constants and RegExps.
- **Deferral.** Postpone hidden KaTeX and inactive-tab work (`lazyInit`, `onVisible`, `requestIdleCallback`). Use `content-visibility: auto` on long off-screen blocks. Off-screen charts coalesce updates and resizes into one render (§10). The gallery loop runs only while its viewer (scene and charts) is on screen (GAL-13). The tfengine updates its charts first, yields, and then re-typesets only the open steps near the viewport (TFE-15).
- **Targets:** 60 fps simulations, INP < 200 ms, CLS < 0.1 (chart frames reserve their space; measured below 0.05 after audit round 1). No task longer than about 120 ms during lazy initialisation at 1× CPU.

## 15. Testing

### 15.1 Unit tests (`node:test`)

- **Location and runner.** Files are `tests/unit/<key>[.<topic>].test.mjs`. Run one with `node --test tests/unit/<key>.test.mjs`; run all with `npm test`.
- **Loader.** Load classic scripts with `tests/helpers/load.mjs`:

  ```js
  import { loadDSL, createEnv, toPlain, SCRIPTS } from '../helpers/load.mjs';
  const { DSL, env } = loadDSL(['js/core/numeric.js', 'js/core/tf.js']);   // ns.js is prepended
  ```

- **Controllable environment:**
  - `env.tick(ms)`, `env.frame(ms)` and `env.frames(n)` drive the fake clock, timers and rAF.
  - `env.setMedia(query, bool)`, `env.setHidden(bool)`, `env.intersect(el, bool)` and `env.resize(el, w, h)` drive the media queries, tab visibility, IntersectionObserver and ResizeObserver.
  - `env.setCssVar(name, value)` sets a computed CSS variable.
  - `env.storage` exposes the fake `localStorage`; `{ storage: 'throw' }` makes every access throw.
  - `env.console.error` and `env.console.warn` collect console output.
  - `env.fire(el, type, init)` dispatches an event.
  - `env.domReady()` fires `DOMContentLoaded`.
  - A minimal fake DOM (`FakeElement`) supports `h()`/`svg()`, attributes, classList, dataset, events, simple selectors and a recording 2D context. It does **not** parse `innerHTML`.
- **`Math.random` throws** inside the context.
- **Cross-realm caveats.** Objects created inside the vm have different prototypes:
  - compare with `assert.deepStrictEqual(toPlain(x), expected)`;
  - match errors by name (`assert.throws(fn, { name: 'TFInputError' })`), never `instanceof`;
  - use `Array.isArray`, never `instanceof Array`, in shipped code too.

### 15.2 End-to-end tests (`@playwright/test` 1.63, Chromium headless shell, `file://`)

- **Location and import.** Files are `tests/e2e/<key>[.<topic>].spec.mjs`, and every spec imports from the fixtures: `import { test, expect } from '../helpers/fixtures.mjs'`.
- **Fixtures:**
  - **`guard`** (automatic) fails the test on any `console.error`, `pageerror`, failed request, or request outside `file:`/`data:`/`blob:`/`about:`. Use `guard.allow(/regex/)` only with a stated reason.
  - **`gotoApp(hash?, { reducedMotion })`** opens the project's page and waits for `html[data-ready="true"]`.
  - **`gotoTestPage('<key>.html')`** opens an isolated page under `tests/pages/` (src only).
  - **`TIMING`** (an export, audit round 2) is `{ tag: '@timing' }`, the details of a test that bounds real time: `test('…', TIMING, async ({ page }) => { … })`. See «Projects» and «Timing-sensitive tests».
- **Projects (audit round 2).** Each page has two projects. `src` (`index.html`) and `dist` (`dist/sistemas-dinamicos.html`) run every test without the `@timing` tag (`grepInvert`). `src-timing` and `dist-timing` run the tagged tests on the same page with one worker each (`workers: 1`, `grep`). `src` names `src-timing` as its `teardown`, and `dist` names `dist-timing`. Playwright therefore runs a timing project in a later phase: it starts once its own project has finished, runs even if that project had failures (a teardown has no dependency to fail), and runs with no other test of the run in progress. In a run of both pages, `src-timing` and `dist-timing` share that last phase, so at most one timing test per page runs at a time. They are not chained (one as the other's teardown): Playwright counts a teardown's teardown among the projects a teardown waits for, so a chain waits for itself and neither project runs. Builders run `--project="src*"` (the wildcard selects `src` and `src-timing`), because the dist file is rebuilt by the integrator only.
- **Commands.** Run each spec in the foreground with a timeout, using its own output folder and `--no-deps`:

  ```
  timeout 300 npx playwright test tests/e2e/<key>.spec.mjs --project="src*" --no-deps --output "test-results/<key>"
  ```

  `--no-deps` matters. Playwright runs a teardown project whole: file arguments and `-g` reach only the projects you selected. Without it, any filtered run of `src` also runs all 31 timing tests of `src-timing` at one worker, about 3 minutes more. With it, the spec's timing tests run in `src-timing` next to the rest of the spec, which is fine for one spec on an idle machine.

  Screenshots go to `testInfo.outputPath('<nombre>.png')`, which lands inside `test-results/<key>/`.
- **Full runs (audit round 2).** One command runs everything:

  ```
  npx playwright test --output "test-results/<run>/full"
  ```

  Phase 1 is `src` and `dist` at the default 4 workers. Phase 2 is `src-timing` and `dist-timing`, one worker each. Build first (`npm run build`), because `dist` and `dist-timing` test the built file. The run takes 17 to 19 minutes on the reference machine (4 workers, 8 logical CPUs), about 3 of them in phase 2. So it does not fit a 10-minute foreground limit: run it in the background with its output in a log, never in a polling loop. One page: `npx playwright test --project=src` runs `src` and then `src-timing`, and `--project=dist` likewise. Splitting by spec by hand is no longer needed. Counts: 311 tests per page, 280 untagged and 31 tagged. 102 of them use test pages and are skipped in `dist` (99 in `dist`, 3 in `dist-timing`); every other test runs on both pages, and no test is skipped in `dist` by an explicit `test.skip(isDist)`. The axe checks live inside the gallery, hero-concepts, shell, tfengine and wizard specs.
- **Timing-sensitive tests (`@timing`).** A test takes `TIMING` when it bounds real time, or simulated progress per real interval. These are the 31: LCP and CLS at four sizes (FND-06); long tasks and phase budgets during lazy init (GAL-04, both GAL-12 tests, TFE-15 idle, the four WZ-08 builds and the WZ-08 5 s jump, HC-12); Event Timing at 4× CPU (TFE-15); `mount()` under 150 ms (tfengine); the wizard step choreography (WZ-01); the gallery's 1×/4× speed ratio (the eight «reproduce, pausa, reinicia, velocidad…» tests); 60 fps of the «tiempo» loop (HC-07); the frame-interval median while the gallery plays (integration); opacity 1 within 100 ms after a jump (FND-07); and, on test pages (`src` only), the 30 fps push burst, «Ver datos» following data within 500 ms (FND-01) and the scene `render()` cost under 2 ms. Within one run nothing else competes with them. Several Playwright runs at once (for example parallel agents) still load the whole machine, so keep to one run at a time. If a timing test fails while the machine is busy, re-run `--project=src-timing` alone before treating it as a regression.
- **Required visual checks** for anything visible:
  - viewports 1440×900 and 1024×768, plus a 390×844 sanity check;
  - zero console errors;
  - no horizontal overflow (`scrollWidth ≤ innerWidth`);
  - the reduced-motion variant;
  - open the screenshots and critique them against SKILLS_BRIEF.
- **Test pages** (`tests/pages/<key>.html`) load `../../vendor/...`, `../../css/tokens.css`, `../../css/base.css` and the needed `../../js/...` files in contract order. `gotoTestPage` waits only for `load`. A page that renders asynchronously should set `<html data-ready="true">` when it is ready, and its spec should wait for that.

## 16. Decisions (conflicts resolved)

1. **Decimal mark.** Displayed numbers use the decimal **point**, a ground rule that overrides SKILLS_BRIEF's `Intl.NumberFormat('es')` comma. Inputs accept both `,` and `.`. Speed labels read «0.25×».
2. **Nav label.** The nav label for `#galeria` is «Galería» (the user's term), not «Simulaciones» as in the brief.
3. **Routing.** Navigation uses plain section anchors (`#galeria`). There is no state in hash routes in v1: the brief's `#/simulaciones/rlc?R=…` deep links are not adopted, and only the theme persists.
4. **Browser tests.** They use `@playwright/test` in Node (pinned 1.63.0 to reuse the installed Chromium 1243), not Python Playwright. The readiness signal is `html[data-ready="true"]`, as in the brief.
5. **Fonts.** Bricolage Grotesque (variable, opsz+wght) and IBM Plex Sans (variable, wght; latin, latin-ext, greek, plus italic) are vendored from `@fontsource-variable` for the dev page too. There is no Google Fonts `<link>`, because the page must not touch the network.
6. **Wizard steps.** The wizard follows the user's four steps (Delimitar, Aplicar leyes, Formular, Simular y validar). The brief's system-dynamics material (causal loops, stocks and flows) lives inside steps 1–2 for SIR.
7. **Hero.** PRODUCT_SPEC (an animated canvas background plus calls to action) takes precedence over the brief's "live mass-spring hero". The hero may still use that motif in its canvas.
8. **Output file.** The single-file build is `dist/sistemas-dinamicos.html`, not `dist/index.html`.
9. **Notation.** The minus sign is typographic `−` in text and ASCII `-` in TeX. The imaginary unit is **j**.
10. **Light theme.** It is a token remap under `[data-theme="light"]`. Dark is the default, whatever the OS preference.
11. **CSS framework.** Hand-written CSS with tokens and cascade layers replaces Tailwind (allowed by the request: «equivalente moderno»).
12. **Library versions** (pinned exactly, each published at least two weeks before scaffolding):

    | Package | Version |
    |---|---|

    | katex | 0.16.47 |
    | lucide-static | 1.50.0 |
    | @fontsource-variable/bricolage-grotesque | 5.3.0 |
    | @fontsource-variable/ibm-plex-sans | 5.3.0 |
    | @playwright/test | 1.63.0 |

13. **Pelucave transition (§20).** The user's integration directive asks for the kinematics calibrated in the sibling harness with its parameters used **exactly**, which includes an `elastic.out(1.2, 0.35)` recovery. The user wins over §14.5 («no bounce or elastic curves»), for this transition only. - **Source of truth.** The kinematics (anticipation → jaw opening → ejection → elastic recovery) is calibrated **only** in the sibling harness repository «la mejor page» (tag `v2-calibrated-export`). Its exported JSON is pasted verbatim into `js/anim/pelucaveParams.js` and frozen; `tests/unit/pelucave.test.mjs` carries a literal copy, so no value can drift. Nothing is tuned in this repository.
- **Files.** `js/anim/pelucaveParams.js` (params + fixed asset geometry), `js/anim/pelucaveAsset.js` (generated by `tools/pelucave.mjs` from `tools/pelucave/svg-completo.svg`), `js/anim/pelucaveTransition.js` (`DSL.anim.pelucave`), `js/anim/pelucaveOverlay.js` (`DSL.anim.pelucaveOverlay`), `css/pelucave.css` (`pv-*`, in `@layer components`), `tests/pages/pelucave.html` (isolated page).
- **Loading.** The four scripts load after the scenes and before the sections (§3) and only define. They touch no DOM, timer or `localStorage` at load time and run without Chart.js and KaTeX (`contract.test.mjs`).
- **Engine.** No GSAP (decision 13). `createTimeline(params).stateAt(t)` is a pure function of time over a 19-channel state (the harness state object); `createRig(container, opts)` builds the layered SVG with `DSL.util.svg` (per-instance ids from `DSL.util.uid`), writes `transform="matrix(…)"` attributes computed in user units of the `0 0 762 734` viewBox (never CSS `transform-origin`), one write per node and frame and only on change, and runs on the shared ticker `DSL.util.loop`. No layout reads: the pieces' rest boxes are constants.
- **Motion rules.** Under `DSL.prefs.reducedMotion`, `play()` jumps to the final state and calls `onComplete` at once. Colours come only from tokens: `--pv-ink` (default `--ink`) and `--pv-paper` (default `--bg`), overridable on the host container.
- **Trigger (hero → gallery).** The hero's «Simular un sistema» anchor (`href="#galeria"`, owner hero-concepts) calls `DSL.anim.pelucaveOverlay.navigate('galeria')` on click and prevents the default only when it returns `true`; otherwise the shell's anchor handling (§12.3) runs as before. `navigate` returns `false` under reduced motion or if the module is incomplete, and `true` while a transition is already running (repeated clicks are swallowed: the lock).
- **Sequence.** `navigate` appends a fixed `div.pv-overlay` to `<body>` (below the header: `z-index: calc(var(--z-header) - 1)`, `pointer-events: none`, `aria-hidden`) holding a `--bg` veil and the head, sized so that the rest ejection point lands at 32 % × 52 % of the viewport. Anticipation fades the veil in; apertura holds it; at `climax` the module jumps to the section with `shell.scrollTo(id, { instant: true })`, reads its rect once, sets `transform-origin` to the landing point of the calibrated trajectory and, each frame, `transform: translate(…) scale(dummyS)` following the ejected object (`distancia 260`, `elevacion −40`, in logo units × head scale) while the veil fades out; at `recuperacion` the section settles (inline `transform`/`transform-origin` removed, class `pv-vuelo` removed, empty `style` attribute dropped) and the head closes elastically, fading in its last 0.3 s. On completion the overlay is hidden, the rig destroyed, the node removed and the section focused (`tabindex="-1"`, `preventScroll`). No style or layer survives that could block the gallery's controls.
- **Not wired on purpose.** The header/menu «Galería» links and the other anchors keep the shell's smooth scroll: the transition is the hero's primary call to action only.
